# Bloquear — plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Que una persona pueda bloquear a otra: no se borra nada, pero nada suyo te llega y deja de ver tu foto.

**Architecture:** Tabla `bloqueos` y una migración (`supabase/migrations/20261116000003_bloquear.sql`, paso de publicación 2.32). La base de datos se encarga de lo importante: oculta los mensajes 1 a 1 con `mensaje_oculto`, que ya existe y que todas las listas de mensajes y el contador de no leídos ya filtran. También descarta notificaciones, no deja sonar las llamadas y vacía la foto. El front sabe a quién he bloqueado yo (nunca quién me ha bloqueado a mí) y con eso pinta los botones, el aviso donde escribes y los mensajes de grupo tapados.

**Tech Stack:** Supabase (Postgres, RLS, realtime `postgres_changes`), Next.js + React (fremee/), lucide-react.

**Spec:** `docs/superpowers/specs/2026-11-16-bloquear-design.md`

## Global Constraints

- Bloquear no borra nada: ni chats, ni mensajes, ni amistades, ni seguidores, ni gastos, ni actividades.
- Al bloqueado no se le avisa nunca. Ningún error ni texto que vea él puede decir «bloqueado».
- `bloqueos` no se toca directamente desde el cliente: `revoke all` y acceso solo con funciones `security definer`.
- Ninguna función devuelve al cliente quién ME ha bloqueado.
- Seguir se oculta en la interfaz, pero la tabla `seguidores` y su código se quedan.
- No hay nada de Reportar ni lista de «Personas bloqueadas» en Ajustes.
- Textos exactos: «Bloquear», «Desbloquear», «Has bloqueado a {nombre} · Desbloquear», «Mensaje de una persona bloqueada».
- Las migraciones las aplica el usuario (primero dev, luego prod). El agente solo puede ejecutar `supabase db query --remote --read-only` contra dev.
- Commits en español, terminados con `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Sin textos que expliquen lo obvio en la interfaz.

## Review Focus

1. **Realtime:** un mensaje de Marcos en el 1 a 1 no puede aparecer en vivo en la pantalla de quien lo bloqueó (la política de `mensajes` debe excluir `mensaje_oculto`). → Tarea 2, comprobación E2E en la Tarea 6.
2. **Vista previa de la lista de chats:** `chat.last_message` es compartido. Quien bloquea no puede ver el texto de Marcos en su lista y el chat no puede subir arriba. → Tarea 2.
3. **«Visto»:** Marcos nunca ve como leído un mensaje enviado después del bloqueo, aunque el otro abra el chat. → Tarea 2 (`fn_chat_lecturas`).
4. **Desbloquear:** lo enviado durante el bloqueo sigue oculto; lo nuevo llega. → Tarea 2, E2E en la Tarea 6.
5. **Grupo creado por Marcos con quien le bloqueó dentro:** no lo añade y no sale ningún error que lo delate. → Tarea 3.

### Task 1: Tabla `bloqueos` y funciones básicas

**Files:** Create `supabase/migrations/20261116000003_bloquear.sql` (sección 1) · Modify `VERIFICACION_PUBLICACION.md`

**Interfaces — Produces:**
- `public.bloqueos (bloqueador_id uuid references auth.users on delete cascade, bloqueado_id uuid references auth.users on delete cascade, created_at timestamptz default now(), primary key (bloqueador_id, bloqueado_id), check (bloqueador_id <> bloqueado_id))`, índice en `(bloqueado_id)`, RLS activado, sin políticas, `revoke all from anon, authenticated`.
- `fn_bloqueado_por(p_bloqueador uuid, p_bloqueado uuid) returns boolean`: stable, security definer, interna (solo `service_role`). La usan todas las demás secciones.
- `fn_bloquear(p_user_id uuid) returns void`: `insert … on conflict do nothing`. Falla con `22023` si `p_user_id = auth.uid()`.
- `fn_desbloquear(p_user_id uuid) returns void`.
- `fn_mis_bloqueados() returns uuid[]`: solo a quién he bloqueado yo.
- Las tres públicas: `revoke from public, anon` y `grant to authenticated, service_role`.

### Task 2: Mensajes, lista de chats y lecturas

**Files:** Modify `supabase/migrations/20261116000003_bloquear.sql` (sección 2)

**Interfaces — Consumes:** `fn_bloqueado_por`. **Produces:** `fn_mensaje_preview(m mensajes) returns text`, interna.

- [ ] **Step 1: trigger `trg_mensaje_bloqueo_antes` (BEFORE INSERT en `mensajes`).** Si el chat es `DIRECTO` y el remitente ha bloqueado al otro miembro, falla con `raise exception 'No puedes escribir en este chat' using errcode = '42501'`. Esto solo lo ve quien bloquea.
- [ ] **Step 2: trigger `trg_mensaje_bloqueo_despues` (AFTER INSERT en `mensajes`).** Para cada miembro de un chat `DIRECTO` que ha bloqueado a `new.sender_id`, inserta `(miembro, new.id)` en `mensaje_oculto`. Va con trigger y no dentro de `fn_mensaje_send` porque la política `mensajes_insert` también permite insertar directamente desde el cliente.
- [ ] **Step 3: política `mensajes_select`.** Se recrea con la condición actual más `and not exists (select 1 from mensaje_oculto o where o.user_id = auth.uid() and o.mensaje_id = mensajes.id)`. Así realtime tampoco entrega el mensaje oculto (y de paso arregla lo mismo para «Eliminar para mí»).
- [ ] **Step 4: `fn_mensaje_preview`.** Se saca a esta función el `case` de vista previa de `fn_mensaje_send` (`20261115000007_chat_info.sql:897-904`), y `fn_mensaje_send` pasa a usarla sin cambiar su comportamiento.
- [ ] **Step 5: `fn_chats_list`.** Se recrea a partir de la versión de `0007:758`. Si el último mensaje del chat está en `mensaje_oculto` para mí, `last_message` y `last_message_at` salen del último mensaje que sí veo (`fn_mensaje_preview`). Si no veo ninguno, se usa `chat.created_at`, y la ordenación usa ese mismo valor. El resto queda igual.
- [ ] **Step 6: `fn_chat_lecturas`.** El `last_read_at` de un miembro que ha bloqueado a `auth.uid()` se devuelve como `least(last_read_at, bloqueos.created_at)`.
- [ ] **Step 7:** Añadir a la fila 2.32 las comprobaciones `select count(*) from pg_trigger where tgname in ('trg_mensaje_bloqueo_antes','trg_mensaje_bloqueo_despues') and not tgisinternal;` → **2** y `select pg_get_expr(polqual, polrelid) like '%mensaje_oculto%' from pg_policy where polname = 'mensajes_select';` → **true**.
